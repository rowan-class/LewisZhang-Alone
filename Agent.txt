# Alone - 设计与需求整理

## 1. 项目清理与基础结构

- 删除目前的三种手感和手感切换，仅保留一种基础手感。
- 跳跃只保留基础跳跃，不再根据按键时长产生不同跳跃高度。
- 去除旧的 level 切换、切换方块 entity，只保留一个 level。
- 去除所有敌人 entity、spike、alien。
- 去除旧 grid 系统。
- 做好模块化，不同系统/实体拆分到不同文件。
- 所有输入都走 `Input.cs`。

## 2. Debug 模式

- 在 `Game1.cs` 中放一个 boolean 控制 debug 模式。
- 按 `F3` 可以在游戏内切换 debug。
- Debug 模式下显示所有 entity 的碰撞箱。
- Debug 模式下可以调整速度：
  - `[` 减小速度，速度不能低于 0。
  - `]` 增加速度。
- Debug 模式下显示当前行驶距离。
- Debug 模式下显示模块状态、事件状态、损坏状态等信息。

## 3. 世界、车辆与镜头

### 3.1 世界运动方式

- 车在玩家感觉中向前移动，但实际上车本体不动。
- 真正移动的是背景、地面物品和镜头。
- 世界大小改为 `5120*1600`。
- 摄像头主要仍以中间 `2560*1440` 区域为核心，多出来的空间用于镜头前探和震动。

### 3.2 摄像机视角

- 两种视角：
  - 车内视角：玩家在车内时，镜头拉近到车内。
  - 全景视角：显示更大的世界区域。
- 玩家按 `Shift` 可以在车内视角和全景视角之间切换。
- 玩家离开车时自动切到全景。
- 当车向前移动时，镜头会向车前方，也就是右侧，产生前探。
- 前探幅度和车速相关。
- 行驶过程中会随机产生镜头震动，全景和车内视角都要有。

## 4. 车辆运动系统

- 车辆状态：
  - 有动力
  - 无动力
- 有动力时：
  - 车辆加速。
  - 到达极速后不再继续加速。
- 无动力时：
  - 车辆减速，直到停止。
- 车辆还没完全停下时，从无动力切换回有动力，可以从减速转为加速。
- 车辆有速度、加速度和最大速度。
- 速度体现在背景、世界物品、镜头运动上。

## 5. 玩家系统

- 玩家可以使用 `WASD` 和方向键移动/跳跃。
- 玩家可以在车上走，也可以在地面上走。
- 玩家是否跟随车辆移动，使用车舱矩形判断。
- 玩家贴图：
  - 游戏内尺寸和碰撞箱为 `48*48`。
  - `Content/player/player1.png`、`player2.png`：走路两帧。
  - `player3.png`、`player4.png`：搬东西两帧。
  - `player5.png`：起跳帧。
  - 所有贴图默认向右，向左移动时需要水平翻转。

## 6. 碰撞与地形

- 需要一个虚假的地面 entity，用于玩家和物品碰撞。
- 车内部有分层、墙、平台等结构。
- 车内碰撞箱用手写 `Rectangle` 指定。
- 这些碰撞箱都要在 debug 模式下显示。

## 7. 物品与坐标空间

### 7.1 掉落物基础规则

- 路上会刷新物品，目前包括：
  - 燃料桶
  - 维修枪
- 物品被丢下时需要受重力下落。
- 玩家按 `G` 可以捡起物品，抓在手上带上车。
- 玩家再次按 `G` 可以丢下物品。
- 物品可以丢在车上，也可以丢在地上。

### 7.2 坐标空间

- 掉落物使用坐标空间区分归属。
- 每个物品有：
  - `Space`：`World` 或 `Vehicle`
  - `LocalPosition`
- 地面物品属于 `World`，会随世界滚动。
- 车内物品属于 `Vehicle`，位置相对车辆稳定，不受世界滚动影响。
- 切换归属时只需要转换坐标：
  - 世界坐标 ↔ 车辆局部坐标

### 7.3 放下物品时的碰撞问题

- 问题：
  - 被玩家拿着的物品不和车辆碰撞。
  - 玩家贴墙时，物品可能已经重叠进墙体。
  - 松手后，物品可能因为碰撞修正瞬移到车顶。
- 当前解决方案：
  - 放下时先检测手持位置是否和碰撞箱重叠。
  - 如果不重叠，放在玩家左/右手持位置。
  - 如果重叠，改放在玩家当前位置。

## 9. 燃料系统

### 9.1 油量

- 油量写在 `VehicleEntity.cs` 中更合适，因为它直接属于车辆。
- 油量随车辆前进减少。
- 加速中油耗更高。
- 到达极速巡航后油耗更低。
- 使用两个不同油耗值。

### 9.2 油量显示

- 创建一个燃油显示 entity。
- 它在车上，相对于车固定。
- 暂时使用蓝色方块。
- 高度按燃油比例变化。
- 下底线位置不变，只改变高度。
- 坐标对齐它的左下角。

## 10. 加油系统

- 放在车内第二层左边。
- 由两个组件组成：
  - 放入油桶的加油口/箱子。
  - 一个按钮。
- 玩家拿着油桶走到加油口前，如果加油口不是点亮状态，加油口打开。
- 玩家按 `G` 松手后，油桶放入加油口，消耗手上的油桶，槽位点亮。
- 玩家跳起来顶按钮时：
  - 槽位从点亮变为不点亮。
  - 车辆加 30% 油。
- 如果槽位已经点亮，玩家按 `G` 只会丢下油桶，加油口不会打开。

### 10.1 加油资源

- 按钮：
  - `Content/modules/button/button1.png`：未被顶。
  - `Content/modules/button/button2.png`：被顶。
- 加油口：
  - `Content/modules/fuel_port/fuel_port1.png`：未点亮关闭。
  - `Content/modules/fuel_port/fuel_port2.png`：未点亮开启。
  - `Content/modules/fuel_port/fuel_port3.png`：点亮关闭。

## 11. 速度推杆

- 具体要求位于 `note/速度杆.txt`。
- 推杆被推动后控制车辆动力。
- 手刹、事件锁定、损坏等情况下，推杆进入快速复位。
- 损坏时：
  - 推杆进入快速复位。
  - 复位过程中不能再被推动。
  - 修好前不输出动力。

## 12. 手刹系统

- 手刹按钮和加油按钮使用同一套按钮贴图。
- 安置在顶楼天花板上。
- 玩家跳起来顶到它后触发。
- 触发后车辆开始快速减速，比无动力减速更快。
- 开关保持按下状态直到速度为 0。
- 如果效果没有触发，按钮不显示被按下。
- 手刹按钮被按下后，速度推杆立刻进入快速复位状态。

## 13. 自动拾取物品模块

- 类似吸尘器。
- 位置在车最下面一层最右边。
- 使用 `Content/modules/suck.png`。
- 当前尺寸：`64*96`。
- 游戏一开始就在车上。
- 初始状态是损坏，需要玩家用维修枪修好。
- 损坏时：
  - 显示红色闪烁。
  - 不会自动拾取物品。
- 修好后：
  - 吸取框向下，宽度与模块一致，一直到地面。
  - 地上的掉落物进入吸取框后会被吸起来。
  - 物品接触模块后，出现在车最下面一层右边的存放位置。
- Debug 模式下按 `7` 可以切换显示/启用变量。

## 14. 太阳能系统

### 14.1 太阳能板

- 太阳能板是车上的可获得组件。
- 当前贴图：
  - `Content/modules/solar/solarpanel1.png`：有能量模式，白天/可用。
  - `Content/modules/solar/solarpanel2.png`：无能量模式，夜晚/沙尘暴/不可用。
- 两张贴图都是 `600*54`。
- 当太阳能可用且按钮按下时，车辆获得速度加成 `+50`。
- 即使没燃油，也可以提供太阳能速度加成。
- 最高速度仍然不超过车辆最大速度。

### 14.2 昼夜与天气

- 事件系统中有白天和黑夜切换事件。
- 白天：
  - 使用 `solarpanel1.png`。
  - 太阳能按钮允许按下。
- 黑夜：
  - 使用 `solarpanel2.png`。
  - 太阳能按钮自动弹开。
  - 太阳能按钮不能按下。
- 沙尘暴期间：
  - 太阳能板和黑夜时一样不可用。
  - 沙尘暴结束后，如果仍是白天则恢复可用。

### 14.3 太阳能按钮

- 和加油按钮使用同一套按钮贴图。
- 跳起来可以按下，再跳起来可以取消按下。
- 手刹被按下时，太阳能按钮取消按下。
- 太阳能不可用或损坏时按钮不能按下。
- 夜晚按钮显示黑白/灰色。
- 损坏时按钮红色闪烁。
- Debug 模式下按 `8` 可以切换太阳能板安装/显示变量。

## 15. 事件系统

### 15.1 基础规则

- 使用 serialization/deserialization。
- 用 `data/events.json` 决定在什么距离发生什么事件。
- 事件以距离为触发条件。
- 事件类型包括：
  - `component_failure`：部件损坏。
  - `solar_install_station`：大型事件，太阳能板安装站。
  - `sandstorm`：天气事件。
  - `repair_gun_drop`：固定距离掉落维修枪。
  - `solar_day` / `solar_night`：昼夜切换。
  - `dialogue`：对话。

### 15.2 可优化点

- 当前事件系统按距离触发，但如果事件很多，每帧扫描所有事件不够高效。
- 更理想的实现：
  - 加载时按触发距离排序。
  - 每帧只检查下一个未触发事件。
  - 如果当前距离达到，就连续触发所有已到距离的事件。
  - 如果没达到，就停止检查。
  - 已激活的持续事件单独维护 active list。

## 16. 大型事件：太阳能板安装站

- 车辆进入安装站后，自动移动到安装需要的位置。
- 到位后车辆不能动，防止玩家停车位置不对或直接开走。
- 安装站是固定在路上的场景，不随车移动。
- 安装站由：
  - 背景。
  - 一组平台碰撞箱。
  - 顶层按钮。
- 碰撞箱只有在车到位之后才生效，避免卡住车里的人。
- 玩家按下顶层按钮后：
  - 太阳能板从上往下降到车上。
  - 动画结束后，将车辆的太阳能安装 bool 设置为 true。
  - 用于动画的太阳能板消失或不再需要。
- 进入站时，速度推杆立刻进入快速复位。
- 太阳能板安装完成前不能推动速度推杆。

## 17. 天气事件：

沙尘暴

- 使用 `Content/weather/sandstorm.png`。
- 贴图是 `3000*1600`，高度对齐世界 `5120*1600` 的 `1600`。
- 沙尘暴从屏幕右侧边框外滑入。
- 完全滑出左侧后才消失。
- 多张沙尘暴贴图之间需要重叠一部分，形成无缝连续效果。
- 每一层/每一张速度略有不同，增加视觉层次。
- 沙尘暴期间太阳能板不可用。

闪电

和沙尘暴一样，在一段距离内



## 18. 损坏与维修系统

### 18.1 可损坏部件

- 加油口。
- 太阳能板。
- 油门/速度推杆。
- 自动拾取模块。

### 18.2 损坏表现

- 发生故障后，部件进入不可用状态。
- 对应按钮也不可用。
- 部件进入红色闪烁视觉效果。
- 事件系统可以定义在哪个距离发生故障。

### 18.3 维修枪

- 维修枪是一个可拾取物品。
- 在事件系统中固定距离刷新。
- 所有部件使用同一个维修枪，不是一个部件一种维修枪。
- 暂时使用和油桶一样大小的蓝色方块代替贴图。
- 玩家拿着维修枪碰到损坏部件时，部件修好。
- 修好时全屏闪一下绿光。

## 19. 对话系统

- 作为事件系统的一种事件。
- 按距离触发。
- 使用 `TextBoxEntity.cs` 绘制 galgame 式对话框。
- 对话框位于屏幕底部。
- 左边显示说话人的头像。
- 右边显示文字。
- 一个距离可以写多句对话。
- 触发对话时，其他所有东西暂停。
- 所有对话播放完成后，游戏继续。
- 头像资源位于 `Content/profile/`：
  - `houston.jpg`
  - `player.jpg`
